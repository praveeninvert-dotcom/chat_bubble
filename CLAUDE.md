## What this project is

A personal bridge that lets one person drive one of their own claude.ai
conversations from a small always-on-top window floating above their other Mac
apps.

A Chrome extension runs on claude.ai, reads conversation turns out of the page,
and sends them over a WebSocket to a local Electron desktop app. Prompts typed in
the bubble travel back and get typed into the claude.ai composer by the
extension.

**Everything runs on one machine. Nothing touches the internet.**

**Personal tool. Single user. Not multiplayer, not published, not a product.**
If a request implies multiple users, remote access, or distribution, stop and
flag it rather than designing for it.

## Who you are working with

The operator is **not a programmer**. They can copy commands, paste output, read
plain English, and use a browser. They cannot review your code for correctness.

This changes how you work:

- Explain what you are about to do in plain language **before** doing it.
- After each change, say what to run to verify it and what a good result looks
  like.
- Never skip a step because it is obvious.
- Prefer fewer moving parts over elegant abstractions. Boring code wins.
- Ask before installing any dependency. Justify it in one sentence.
- If something fails, give an exact command to run and ask for the full output.
  Do not guess.
- The operator is on **macOS**. `sed -i` needs an empty argument (`sed -i ''`).
  Prefer commands that work as written on a Mac.

## Locked decisions — do not relitigate these

| Decision | Value | Why |
|---|---|---|
| Architecture | Local only. Electron app on `127.0.0.1:8787`. No cloud. | Both ends are on one machine. A round trip to the internet served no purpose. |
| Desktop framework | Electron, not Tauri | Tauri needs Rust. Electron is JavaScript throughout and the React bubble ports unchanged. |
| WebSocket location in extension | **Content script**, not the background service worker | MV3 service workers are killed when idle and drop the socket. Revisit only if Chrome blocks `ws://localhost` from an HTTPS page. |
| Server binding | `127.0.0.1` only, never `0.0.0.0` | Binding to all interfaces would expose the server to the local network. |
| Pairing | 32-byte token generated by the **desktop app**, pasted into the extension options page | Any web page can probe localhost. Origin check plus token. |
| Persistence | JSON file in `app.getPath('userData')` | No database needed. No free-tier write budget to respect. |
| History on attach | Backfill the existing DOM with `turn.snapshot`, replacing stored turns | MutationObserver does not fire for nodes that already exist. |
| Response capture | Streaming deltas with an authoritative final message on `turn.end` | The bubble mirrors in real time. See SPEC.md §4. |
| Text injection | `execCommand('insertText')` or synthetic paste — **not** `textContent` | The composer is confirmed `tiptap ProseMirror` with internal state. Direct DOM writes get discarded. |

## Hard rules

1. **Never invent a CSS selector or `data-testid` value.** If `SELECTORS.md` says
   `UNKNOWN`, the code cannot be written yet. Say so and stop. Do not write a
   plausible-looking placeholder that will silently fail.
2. **Never transport authentication material.** The claude.ai session cookie,
   `sessionKey`, org ID, and any bearer token must never enter the WebSocket, the
   desktop app, or the bubble. The relay carries message text and IDs only.
3. **Never call the Anthropic API.** This project deliberately has no API key. If
   a task seems to need one, the design is wrong — flag it.
4. **Do not build on `worker/`.** It is the dead v2 relay, kept only for
   reference.
5. **No secrets in committed files.** The pairing token lives in the desktop
   app's userData directory.
6. **Do not add features.** No accounts, no analytics, no telemetry, no
   multi-conversation support until STATUS.md says the core relay works end to
   end.
7. **Do not edit SPEC.md, CLAUDE.md, or PROMPTS.md without saying so explicitly**
   and describing exactly what changed. These are the operator's source of truth
   and they cannot diff your work.

## Conventions

- Vanilla JS in `extension/`. No bundler, no TypeScript, no npm dependencies.
- The desktop app may use `electron` and `ws`. Anything else needs justification.
- Every WebSocket message is JSON with a `type` field. See SPEC.md §4.
- Log with prefixes `[bubble-ext]`, `[bubble-server]`, `[bubble-ui]` so the
  operator can tell which component spoke.
- Commit after each working phase. Write the commit message yourself.

## Current blockers

1. The extension cannot be built until `SELECTORS.md` Tests 1–4 are filled in.
   That requires the operator to run commands in claude.ai DevTools.
2. Whether Chrome permits `ws://localhost` from an HTTPS page is untested. If it
   is blocked, the socket must move into the background service worker and the
   content script relays over `chrome.runtime` messaging.

`desktop/` and `bubble/` work is unblocked.
